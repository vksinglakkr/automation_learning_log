# 🎭 Lab 5: Dynamic Payload (Persona Injection)

**Objective:** Learn how to inject dynamic variables into an HTTP request body while maintaining strict authentication security.

## 🧠 The Blank Envelope Concept
In Labs 2 and 4, we wrote our instructions to the AI in permanent ink. The system message inside the HTTP node was hardcoded. If we wanted the AI to change from a "teacher" to a "poet," we had to open the HTTP node and carefully rewrite the JSON code.

This is dangerous! Editing raw JSON manually every time you want to change a parameter often leads to broken code and syntax errors. 

The solution is **Dynamic Injection**. We leave a blank space in our JSON envelope (`{{ $json.systemPrompt }}`) and use a separate, user-friendly Set Node to fill in the blank before the envelope is sealed and sent.

## 🛠️ What We Did
1. **The Question Node:** We defined what the user is asking.
2. **The Persona Node:** We created a brand new variable called `systemPrompt` and instructed the AI to speak in rhyming poetry.
3. **The HTTP Node:** We replaced the hardcoded system message with n8n's expression syntax: `{{ $json.systemPrompt }}`.

## 🎓 The Master-Level Lesson
This lab proves that **security and control are two separate things.** 

You can lock down your API key using a secure Generic Header Auth credential (The Lock), while simultaneously keeping your data entirely flexible and dynamic (The Payload). By separating *what* you are sending from *how* you are authenticating it, you are building robust, production-ready systems that can adapt instantly without breaking.
