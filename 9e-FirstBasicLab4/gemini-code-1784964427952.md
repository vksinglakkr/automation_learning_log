# 💳 Lab 4: The Shortcut (Generic Bearer Auth)

**Objective:** Understand how platforms build specific shortcuts for common API authentication patterns.

## 🧠 The Smart Card Concept
In Lab 2, we built our HTTP request manually. We told the system exactly which header to use (`Authorization`) and exactly how to format the key (`Bearer xyz123`). This gave us ultimate control, but it also introduced a risk: **Human Error**.

What if a student types `Authorisation` (with an 's')? What if they forget the space after `Bearer`? The request will fail, and debugging a tiny typo in a header can take hours.

Because thousands of APIs (including Groq, OpenAI, and GitHub) use this exact same pattern, n8n provides a **Shortcut Vault**: The Generic Bearer Auth credential.

## 🛠️ What We Did
1. We changed the authentication dropdown from `Header Auth` to `Bearer Auth`.
2. We provided **only the raw key** in the credential vault.
3. Behind the scenes, n8n automatically assembled the `Authorization: Bearer <key>` string and injected it into the header.

## 🎓 The Master-Level Lesson
**Good engineers are strategically lazy.** 
If a tool provides a built-in shortcut that eliminates typos, you should use it. 

*   Use **Lab 2 (Header Auth)** when you are forced to (e.g., if an API requires a strange header like `x-api-key`).
*   Use **Lab 4 (Bearer Auth)** whenever an API specifically asks for a Bearer token. Let the machine do the typing!
