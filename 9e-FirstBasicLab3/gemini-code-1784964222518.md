# ⚠️ Lab 3: The Danger Zone (Static Header Anti-Pattern)

**Objective:** Understand the catastrophic security risk of hardcoding API keys.

## 🧠 The Sticky Note Password
Imagine buying the most expensive, secure digital lock for your house. But instead of memorizing the PIN code, you write it on a sticky note and paste it right next to the keypad. 

It works. The door opens. But anyone walking by now has your code.

In backend automation, doing this is called an **Anti-Pattern** (a common practice that looks like a solution but is actually a terrible idea). 

## 🛠️ What We Did
1. We bypassed n8n's secure credential system by selecting **Authentication: None**.
2. We manually forced the `Authorization` header into the node's settings.
3. We pasted our raw API key directly into the text field.

## 🎓 The Master-Level Lesson
The workflow executed perfectly. The Groq AI responded. *So why is this bad?*

n8n is designed to share workflows easily. When you use a proper credential (like in Lab 1 and Lab 2), n8n keeps your secret key in an encrypted vault on your computer. If you export your workflow as a JSON file, n8n replaces your key with a placeholder (an ID). 

When you hardcode the key (Lab 3), you are typing it into a standard parameter field. If you click **Download** and open the workflow JSON file in Notepad, your key is sitting there in plain text. If you upload that file to GitHub or share it with a friend, your account is immediately compromised. 

**Always use Credential Vaults. Never leave your keys on a sticky note.**
