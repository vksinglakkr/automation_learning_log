# 📘 Google Sheets CRUD Operations — Learning Log

**Goal:** Treat Google Sheets not just as a static document, but as a dynamic Database using n8n.

## Part 1: The Core Operations (CRUD)
1. **Create (Append/Insert):** Adds a brand-new row at the bottom of the sheet. Used when a new booking arrives.
2. **Read / Lookup:** Searches the sheet for a matching column value (e.g., matching `Ticket ID`).
3. **Update:** Finds the matching row using `Ticket ID` and updates ONLY specified cells (e.g., `Tour Date`), leaving the rest untouched.
4. **Delete:** Finds the row matching `Ticket ID` and completely clears/removes that row.

## Part 2: Matching Columns Rule in n8n
When performing **Update** or **Delete** in n8n's Google Sheets node:
* You MUST specify a **Matching Column** (e.g., `Ticket ID`).
* n8n acts as a detective: it scans the entire sheet, finds where `Ticket ID == KKR-TICK-801`, and applies the changes only to that specific row number.

## 🎓 Classroom Hands-On Setup
1. Create a Google Sheet titled **"KKR Operations"** with columns: `Ticket ID`, `Name`, `Phone`, `Tour Date`.
2. Connect your Google Sheets credential in n8n.
3. Use the HTML console to test:
   - **Step 1:** Run `Insert` $\rightarrow$ Check Google Sheet (New row appears).
   - **Step 2:** Change date to 16th and run `Update` $\rightarrow$ Check Google Sheet (Only the date cell changes!).
   - **Step 3:** Run `Delete` $\rightarrow$ Check Google Sheet (The entire row vanishes!).
