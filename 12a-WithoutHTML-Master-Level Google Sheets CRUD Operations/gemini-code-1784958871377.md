# 📘 Master Class: Google Sheets Database (CRUD)
**Focus:** Pure Backend Engineering & Data Routing

Welcome to the backend! In this module, we have stripped away all the HTML frontends and external webhooks. Why? Because as backend engineers, you need to learn how to test and manipulate data at the core level without being distracted by website design. 

In this lesson, you will turn a simple Google Sheet into a dynamic, living database using **CRUD** operations:
*   **C**reate (Insert new rows)
*   **R**ead (Lookup existing rows by an ID)
*   **U**pdate (Modify specific cells without breaking the row)
*   **D**elete (Remove rows entirely)

---

## 🛠️ Step 1: Database Setup
Before touching the workflow, we need a place to store our data.
1. Create a new Google Sheet and name it **"KKR Operations DB"**.
2. Create exactly these four column headers in Row 1:
   * `Ticket ID`
   * `Name`
   * `Phone`
   * `Tour Date`
3. In n8n, open the Google Sheets nodes and connect your **Google Sheets Credential**. Select the spreadsheet you just created.

---

## 🔍 Step 2: How This Workflow Operates
Instead of waiting for an external website to send us data, we are simulating the data ourselves using a **Set Node**.

1. **Manual Trigger:** This replaces the Webhook. It allows you to run the workflow instantly by clicking "Execute Workflow".
2. **Mock Data Input (Set Node):** This acts as your control panel. You will manually change the variables here to trick the system into thinking a user submitted a form.
3. **Route by Action (Switch Node):** The brain of the operation. It reads the `action` variable from your Mock Data and sends the data down the correct path (Insert, Update, or Delete).
4. **Google Sheets Nodes:** The executioners that actually modify your database based on the routing.

---

## 🚀 Step 3: The Hands-On Exercise
Open the **Mock Data Input (Edit Me!)** node in your n8n canvas. You will perform three tests. 

### Test 1: The Insert (Create)
*   **Action:** Change the `action` field to `insert`.
*   **Data:** Make sure `Ticket ID` is `KKR-TICK-999` and `Name` is your own name.
*   **Execute:** Click "Execute Workflow" at the bottom of the screen.
*   **Verify:** Check your Google Sheet. You should see a brand new row added!

### Test 2: The Reschedule (Update)
*   **Action:** Change the `action` field to `update`.
*   **Data:** Change the `tour_date` field to a new date (e.g., `2026-09-01`). Keep the `Ticket ID` exactly the same (`KKR-TICK-999`).
*   **Execute:** Click "Execute Workflow".
*   **Verify:** Check your Google Sheet. Notice that a new row was **not** created. Instead, n8n hunted down `KKR-TICK-999` and only changed the date! *(This is the power of the "Matching Columns" setting).*

### Test 3: The Cancellation (Delete)
*   **Action:** Change the `action` field to `delete`.
*   **Execute:** Click "Execute Workflow".
*   **Verify:** Check your Google Sheet. The entire row for `KKR-TICK-999` should be completely gone.

---

## 🧠 Key Takeaways
1. **Testing in Isolation:** You do not need a fully built website to test your database logic. Using a Set Node allows you to build and verify your backend perfectly.
2. **The "Matching Column" Rule:** For Updates and Deletes to work, n8n must know *how* to find the right row. We use `Ticket ID` as our unique identifier. If two people have the same name, the system won't get confused because their Ticket IDs are always different.
