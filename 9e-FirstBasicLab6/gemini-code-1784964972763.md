# 🕵️‍♂️ Lab 6: The Code Injector (Data Validation)

**Objective:** Use a Code node (JavaScript) to sanitize data and pre-assemble JSON structures before sending them to an API.

## 🧠 The Quality Inspector Concept
In previous labs, we passed the user's question *directly* into the HTTP node. If the user sent a valid question, it worked. But what if a malicious user tries to send a 10,000-word essay to crash our system or run up our API bill? 

We cannot blindly trust incoming data. We need a "Quality Inspector." 

By placing a Code Node *before* the HTTP Request, we can use JavaScript to act as our inspector. It trims white space, enforces length limits, and organizes the data perfectly.

## 🛠️ What We Did
1. **The Messy Input:** We simulated a user sending a very long question with lots of extra spaces.
2. **The Code Node (JavaScript):**
   * We used `.trim()` to remove the messy spaces.
   * We used `.slice(0, 500)` to guarantee the question is never longer than 500 characters.
   * We constructed the `messages` array manually inside the code block.
3. **The HTTP Request:** Because the Code node did all the hard work, the JSON Body inside the HTTP node became incredibly simple: `{{ $json.messages }}`.

## 🎓 The Master-Level Lesson
This is the true secret of advanced n8n engineering: **Keep your HTTP nodes "dumb."**

An HTTP node should only have one job: sending the data securely. It should not be responsible for cleaning text, formatting dates, or building complex arrays. When you move the data transformation logic into a dedicated Set or Code node, your workflows become infinitely easier to read, debug, and scale.
