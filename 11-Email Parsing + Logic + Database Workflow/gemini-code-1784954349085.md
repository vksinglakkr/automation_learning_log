# 📨 Automated Helpdesk (CMS) — Core Learning Log

**Goal:** Turn n8n into a Digital Receptionist that reads emails, ignores spam, logs real issues to a database, and replies to the user.

## Part 1: The "Trigger" Evolution
Until now, we used **Webhooks** to start workflows (like someone submitting a form). But a real helpdesk runs on emails. 
* **For Testing (Now):** We use a Webhook to *simulate* an email from our HTML console so we can test our logic safely.
* **For Production (Later):** We will delete the Webhook and replace it with a **Gmail Trigger** or **EmailRead (IMAP) Trigger** node. It watches the inbox 24/7 and triggers automatically.

## Part 2: The Logic (Switch Node)
Not every email is a complaint. If Swiggy sends a promotional email to `support@kkrtourguide`, our system shouldn't create a support ticket for it!
* We use a **Switch Node** reading the `$json.body.subject`.
* **Rule:** If the subject contains "offer", "discount", or "promotional", the workflow routes it to a dead end (Drops it).
* **Rule:** Otherwise, it proceeds to the Resolution Desk.

## Part 3: The Resolution Desk (CRUD & Actions)
Once an email is verified as a real inquiry/complaint, the Master-Level operations begin:
1. **Set Node:** Generates a unique Ticket ID using n8n's time expressions: `KKR-{{ $now.toFormat('HHmmss') }}`.
2. **Google Sheets (Create):** Inserts a new row with the Sender's email, Subject, and Ticket ID. This is our Database.
3. **Send Email (Action):** Uses the dynamic Ticket ID to send a personalized auto-reply to the user instantly.
